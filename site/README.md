# 学習サイト公開計画

`site/` は、GitHub Pagesで公開する静的サイト全体の入口です。

実装・検証方法と新しい教材の追加手順は、リポジトリ直下の
[`DEVELOPMENT.md`](../DEVELOPMENT.md) を参照してください。

小さな教材は `site/` の中で、ビルド工程が必要な教材はリポジトリ直下の独立した
ディレクトリで管理します。公開処理では、トップページ、静的教材、各アプリの
ビルド成果物を `dist/` へ集約し、GitHub Pagesへデプロイします。

## この名前にした理由

- `docs/` は設計資料や調査記録と混同しやすく、すでに `kakomon/docs/` でも使っている
- `public/` はViteなどで「加工せずコピーする素材」を指すことが多い
- `site/` なら、公開サイトの入口・案内・共通素材を置く場所だと分かりやすい
- GitHub Pages以外へ移行しても名前が不自然にならない

## 想定する構成

```text
study-chosashi/
├── site/                              # 公開サイトの手書きコンテンツ
│   ├── index.html                     # 教材一覧
│   ├── assets/                        # トップページの共通素材
│   └── civil-rights-transitions/      # 権利変動教材の試作
├── period-flashcards/                 # Viteアプリのソース
├── scripts/build-site.mjs             # 公開用ファイルの組み立て
├── kakomon/                           # 過去問データと整備ツール
└── .github/workflows/pages.yml        # Pagesへの公開処理
```

公開時には、次のURL構成になります。

```text
/
├── period-flashcards/
└── civil-rights-transitions/
```

各アプリは直接URLを開いて使えるようにし、トップページは教材の目次として機能させます。

## 作りたい教材の候補

### 1. 期間フラッシュカード

既存の `period-flashcards/` を最初の公開対象にします。小さく公開手順を確立でき、
スマートフォンでの反復学習にも向いています。

### 2. 民法・権利変動アニメーター

人物、土地、契約、登記、時点を画面上に置き、「誰が誰に対して権利を主張できるか」が
操作に応じて変化する教材です。

最初の題材は一つに絞ります。

- AからBへの売買
- AからCへの二重譲渡
- BまたはCの登記
- 各時点における所有権と対抗関係の表示
- 結論だけでなく、適用する条文と判断理由も表示

発展候補として、取消し・解除後の第三者、相続、取得時効、抵当権を追加します。

### 3. 登記申請シーケンス

事実関係を並べ替え、必要な登記の目的、原因、申請人、添付情報を組み立てる教材です。
誤答時には、実体法上の変動と登記手続上の処理のどちらを誤ったかを分けて示します。

### 4. 土地・境界の図解ドリル

筆界、所有権界、分筆、合筆、地積更正などを簡単な図で比較します。
図を操作した後に、申請の可否や必要条件を答える形式にします。

### 5. 測量計算ミニドリル

座標、距離、面積、誤差などを一問ずつ短時間で解く教材です。途中式を段階表示し、
計算方法の理解と速度向上の両方に使えるようにします。

### 6. 過去問ブラウザー

`kakomon/tsv/` のデータを利用し、年度、分野、キーワードで過去問を絞り込みます。
著作物の扱いと出典表示を確認してから公開対象を決めます。

## 今後の優先順位

1. GitHubへpushし、トップページと2教材をPagesで公開する
2. スマートフォン表示、キーボード操作、アクセシビリティを確認する
3. 権利変動アニメーターに確認問題を追加する
4. 試作を使って学習効果を確かめてから題材を増やす
5. 共通UIが固まった段階で、各教材へ展開する

## 権利変動アニメーターの最小版

最初から民法全体を扱わず、二重譲渡の一つのシナリオだけを試作しました。

1. A、B、Cと一筆の土地を表示する
2. 「A→B 売買」「A→C 売買」「登記」の操作を時系列に追加できるようにする
3. 操作のたびに、実体上の権利変動をアニメーションで示す
4. 現在の登記名義人と、第三者への対抗可否を別々に表示する
5. 「なぜそうなるか」を条文、要件、当てはめ、結論の順で示す
6. 最後に確認問題を一問出す（今後追加）

ここで大切なのは、派手な動きよりも「時点」「実体上の権利」「登記」「対抗関係」を
同時に見失わないことです。アニメーションを停止して各時点を戻れる設計にします。

## コンテンツ作成の共通ルール

- 根拠条文、基準日、出典を明記する
- 法改正の影響を受けるデータと画面ロジックを分離する
- 正解だけでなく、判断過程を短く説明する
- スマートフォンだけでも一通り操作できるようにする
- 色だけで正誤や権利関係を表現しない
- アニメーションの停止・巻き戻し手段を用意する
- URLを直接開いて、特定の教材や問題を共有できるようにする
- 個人の学習補助であり、法的助言ではないことを明示する

## GitHubへアップロードした後の公開手順

1. GitHub上でリポジトリを作成し、このリポジトリをpushする
2. リポジトリの **Settings → Pages** でSourceを **GitHub Actions** にする
3. 用意済みのワークフローが完了するのを待つ
4. 公開URLでトップページと各教材への直接アクセスを確認する

Viteアプリはリポジトリ名を含むURLでも素材を正しく読めるよう、相対パスを使う設定に
しています。公開用の生成物はGitに直接保存せず、Actionsで毎回生成します。

## 今回の範囲

トップページ、二重譲渡権利変動アニメーターの試作、既存の期間フラッシュカード、
GitHub Actionsによる公開設定まで用意しました。ローカルで公開用ファイルを生成するには、
次を実行します。

```bash
pnpm --dir period-flashcards install
pnpm --dir period-flashcards build
node scripts/build-site.mjs
```

生成された `dist/` が、そのままGitHub Pagesへ配信される内容です。

`site/index.html` をファイルとして直接開いた場合も、期間フラッシュカードについては
`period-flashcards/dist/` の生成済みファイルへ移動します。内容を変更した後は、先に
`pnpm --dir period-flashcards build` を実行して表示を更新してください。
