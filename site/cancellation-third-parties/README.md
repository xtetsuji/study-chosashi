# 取消し前・取消し後 第三者シーケンス

詐欺による不動産売買の取消しについて、第三者が登場する時点と適用ルールを
シーケンス図で比較する静的教材です。実体上の所有権、登記名義、取消しの時点を
別々に表示します。

## 教材の中心となる整理

基本編では、AがBとの売買を取り消し、Bから取得した第三者Cとの関係を扱います。

- 取消し前第三者：取消し時点ですでにCがいる。民法96条3項により、Cが善意・無過失かを判断する
- 取消し後第三者：取消し時点ではCがいない。Aの復帰登記とCの移転登記を民法177条で比較する
- AとBは取消しの当事者なので、Aは登記なしで所有権復帰をBに主張できる

画面上の「善無」は「善意・無過失」、「非保護」は96条3項の保護要件を満たさない
状態を意味します。色だけでなく、この文字でも状態を区別します。

## 発展編：CからDへの転売

`dTiming` は変数名にDを含みますが、実質的には取消しが二つの転売のどこに入るかを
表す値です。

| `dTiming` | 時系列 | 判断の入口 |
| --- | --- | --- |
| `before` | B→C、C→D、取消し | CとDはいずれも取消し前。各人の善意・無過失を96条3項で検討する |
| `between` | B→C、取消し、C→D | まずCを96条3項で判断し、その結果を受けてDとの関係を判断する |
| `after` | 取消し、B→C、C→D | CとDはいずれも取消し後。基本事例ではAとDの登記の先後を比較する |

`between` の判断順序は次のとおりです。

1. Cが善意・無過失なら、Cは96条3項で保護され、DはCが確定的に取得した地位を承継する
2. Cが保護されないなら、取消し後に登場したDとAを177条の登記の先後で比較する

この場合、D自身の善意・無過失は基本事例の結論を左右しません。CからDへの承継は、
保護されたCが確定的に権利を取得するとする通説的な「絶対的構成」で整理しています。
背信的悪意者などの例外は教材の対象外です。根拠資料と確認基準日は
`index.html` の「根拠と、この教材の範囲」に記録しています。

## ファイル構成

- `index.html`：画面構造、教材の前提、根拠条文・出典、学説上の注記
- `style.css`：シーケンス図、状態バッジ、レスポンシブ表示、動きの抑制
- `app.js`：基本編のイベント定義、画面状態、描画、操作イベント
- `logic.js`：発展問題の判定とURL状態の変換。ブラウザーとCommonJSの双方から利用する
- `../../tests/cancellation-third-parties.test.js`：判定、URL共有、最低限のアクセシビリティ要件のテスト

法的な判定を変更するときは、表示だけを直さず、先に `logic.js` とテストを更新し、
その結論を `app.js` の説明文へ反映してください。

## URLで共有する状態

「この場面のURLをコピー」で、現在の状態をクエリ文字列へ保存します。

| パラメーター | 主な値 | 意味 |
| --- | --- | --- |
| `scenario` | `before`, `after` | 基本編の取消し前・取消し後第三者 |
| `step` | 0以上の整数 | 基本編の表示ステップ |
| `result` | `protected`, `unprotected`, `a`, `c` | 基本編で選んだ結論 |
| `advanced` | `1` | 発展編を開く |
| `dTiming` | `before`, `between`, `after` | 発展編の取消し位置 |
| `cState`, `dState` | `protected`, `unprotected` | C・Dの善意無過失の状態 |
| `dWinner` | `a`, `d` | AとDのうち先に登記を備えた者 |

URLの読み書きは `logic.js` の `readUrlState()` と `buildUrlSearch()` に集約しています。
パラメーターを追加・変更した場合は、復元と生成の両方をテストしてください。

## 表示を変更するときの注意

- 緑は実体上の所有権、ピンクは登記名義、朱色の点線は取消しを表す
- 所有権が二つあるように断定せず、対抗関係が未決着であることを文章でも示す
- 状態や結論を色だけで表現しない
- キーボードだけで主要操作を完了できるよう、操作要素には `button` を使う
- アニメーションを追加するときは `prefers-reduced-motion` への対応を維持する
- GitHub Pagesのサブパスと `file://` の双方を壊さないよう、素材は相対URLで参照する
- 法的整理を変更した場合は一次資料を再確認し、`index.html` の基準日も更新する

## 検証

リポジトリのルートで次を実行します。

```bash
node --check site/cancellation-third-parties/app.js
node --check site/cancellation-third-parties/logic.js
node --test tests/cancellation-third-parties.test.js
pnpm --dir period-flashcards build
node scripts/build-site.mjs
git diff --check
```

`dist/` は自動生成される公開成果物なので、直接編集・コミットしません。
